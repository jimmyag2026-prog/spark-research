## 第 12 步 · `llmTimeoutMs` 边界

三次都走 `PUT /api/settings/general/llmTimeoutMs`（网页端 number 输入框打不进 `abc`，该值改用 curl 同端点发，等价于界面背后的那一次写）：

```

value="abc"  → HTTP 422   {"error":"'llmTimeoutMs' 必须是数字，收到 'abc'","nextStep":"填一个毫秒数，例如 120000"}
value=30000  → HTTP 200   {"item":{"key":"llmTimeoutMs","value":30000,"source":"config",…}}
```

**判断：不过（三分之一不过）。**`abc` 拒得对，`30000` 收得对，但 **`500` 被接受并写进了 config.json**——任务书的期望是拒绝（下限 1000）。下限校验不存在。见 U22（P1）。

附带发现（反证第 4 步）：`llmTimeoutMs` 这一项写完**立刻**在响应里回显新值且 `source` 标 `config`（不是 `env`）。它与 `defaultModel` 的差别正好是「启动时 config.json 里有没有这一项」——这是 U15 根因的关键对照。
