同一枚令牌、同一秒、只差路由里的 id 形态。`X-Spark-Approval-Token` 请求头走短 id 同样 403。
**照着工具自己的提示做，100% 撞 403，而且错误信息把你指回那条走不通的路**（「在终端跑 `lab token e6c7b682`」——
你刚跑过，它就是不认）。注意第二次使用时的报错**改口印了全 UUID**，说明服务端手里有全 UUID，只是没在第一现场吐出来。

> 我判「过 + High」而不是 Blocker 的理由：这个 bug 是**朝关的方向坏**（fail-shut），
> 门比声称的更紧、不是更松，没有放行任何不该放行的东西。但它让 V95 的 HTTP 审批路径
> 对一个照文档操作的人**完全不可用**，所以不能只算 Low。

### 附带 LOW：权限面板的「有效审批令牌」计数不动

签发第 1、2 枚后显示「算力 0 · 湿实验 2」；再签发第 3 枚、并消费掉其中两枚之后，**仍然显示「湿实验 2」**。
面板自述「令牌 10 分钟后自动失效；用掉一次即作废」，但这个计数既不随签发上涨也不随消费下降。

### 「跑不了」记录：`lab token` / `lab approve` 的 TTY 门（V19）

**这条门我没法在真人终端里验，所以走了产品自己给的 CI 旁路**
