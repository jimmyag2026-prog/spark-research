## 行 4 · 非 loopback 来源写凭据 → 403；加进 originAllowlist 后仍 403

**判据**：任一放行 = Blocker。**结论：不过 —— BLOCKER-1。**

**前半（allowlist 未配时）过**。server 只 bind `127.0.0.1:4321`（`lsof`：`TCP 127.0.0.1:4321 (LISTEN)`），
本机 LAN 地址 `10.255.38.73` 根本连不上；用非 loopback `Origin` 打：

```
$ curl -s -i -X PUT "http://127.0.0.1:4321/api/settings/credentials/semanticscholar" \
    -H 'Content-Type: application/json' -H 'Origin: http://a8-remote.example' \
    -d '{"fields":{"api_key":"..."}}'
HTTP/1.1 403 Forbidden
{"error":"拒绝跨站请求：Origin 'http://a8-remote.example' 不在白名单内"}
```

**后半（加进 originAllowlist 之后）不过。** 关键在于：4321 这个实例是**在我改 `originAllowlist` 之前**启动的，
它至死都拿着旧配置，所以在 4321 上重发照样 403 —— 这个 403 是**配置没热加载造成的假阴性**，不是 AD-18 ② 的牙齿。
用一个**加载了新配置的新实例**（我自己起的 `bun backend/src/index.ts server 4399`）做同一件事：

```
$ cat ~/.spark-research/config.json        # originAllowlist 已写入
{"defaultModel":"deepseek-chat","contactEmail":"...","llmTimeoutMs":30000,"originAllowlist":"a8-remote.example"}

# 对照组：非凭据端点，同一个 allowlist 化的非 loopback Origin —— 200，证明 allowlist 在这个实例上真的生效了
$ curl -s -i -X PUT "http://127.0.0.1:4399/api/settings/general/httpTimeoutMs" \
    -H 'Content-Type: application/json' -H 'Origin: http://a8-remote.example' -d '{"value":31000}'
HTTP/1.1 200 OK
{"panel":"general","item":{"key":"httpTimeoutMs",...,"value":31000,...}}

# 实验组：凭据写入，同一个 Origin —— 应当 403，实际 200 并且真的落盘了
$ curl -s -i -X PUT "http://127.0.0.1:4399/api/settings/credentials/semanticscholar" \
    -H 'Content-Type: application/json' -H 'Origin: http://a8-remote.example' \
    -d '{"fields":{"api_key":"A8-FAKE-KEY-20260915-REMOTE"}}'
HTTP/1.1 200 OK
{"panel":"credentials","item":{"key":"semanticscholar",...,"configured":true,...,"fieldsSet":["api_key"],...},
 "meta":{...,"notes":["值写进来之后永不回显——响应、日志、raw、record、usage 里都不会再出现它（AD-18 ①）",
 "只接受本机（loopback）来源的写入；配了 originAllowlist 也不会放开这条路径（AD-18 ②）", ...]}}
```

**响应体自己印着「配了 originAllowlist 也不会放开这条路径（AD-18 ②）」，而这条响应就是 200。** 落盘核对：

```
$ python3 -c "... credentials.json ..."
  endsWith -REMOTE : True
  updatedAt        : 2026-09-15T10:14:41.434Z
  length           : 27
```

**DELETE 同样被放行**（跨站删凭据）：

```
$ curl -s -i -X DELETE "http://127.0.0.1:4399/api/settings/credentials/semanticscholar" -H 'Origin: http://a8-remote.example'
HTTP/1.1 200 OK
{"panel":"credentials","removed":true,"id":"semanticscholar","note":"只删本机保存的值，不影响外部账户",...}
$ # connectors 剩 ['aminer']
```

判定：`originAllowlist` 里的非 loopback 来源可以**写入并删除**凭据 → AD-18 ② 不成立 → **Blocker**。
（同时说明：T5 第 20 步这条 P0 也不过。）

> 复现最短路径：`config set originAllowlist <任意主机名>` → **重启 server** → 带那个 `Origin` 发
> `PUT /api/settings/credentials/<id>`。不重启就复现不出来，这也是它能一路活到 alpha.3 的原因。
