## 3.1 U71（Blocker）· 综述已交付，用户被告知「无法交付」

三次文献会话，**三次都是**：pipeline 真的生成了综述 artifact 并逐块流给了前端，
而最后那句总结告诉用户「综述无法交付」。

`a9-lit-1` 的 pipeline 结果（`workspaces/a9-lit-1/t1.json`）：

```
ok True  depth quick  mode review  cards 0  downloads 0
review {"artifactId": "2df1e3ed-3591-4d40-bcd0-040beb48e865",
        "path": ".../projects/a9-lit/artifacts/review-draft-2026-09-16.md",
        "citedKeys": 8, "unknownKeys": 0,
        "gap": {"total": 52, "judged": 43, "unresolved": 0, …}}
digestLen 1500          ← 恰好顶满
digest tail: "…- 2016 European Guidelines on cardiovascular disease prevention in clinical practice (2016) doi:10.1177/2047"
```

综述文件真的在盘上（53 行，带 8 个 `[@key]` 引用，全部核验通过）：

```
$ head -3 ~/.spark-research/projects/a9-lit/artifacts/review-draft-2026-09-16.md
## 研究现状

工作相关的上肢与颈部肌肉骨骼疾患（MSD）是全球最常见的职业性疾患之一…[@hoe2018ergonomic]
```

而用户拿到的是：

```
[session a9-lit-1]
## 结论

**小综述目前无法交付**——计划的4个步骤中仅完成了第1–2步的前半段（检索与建库），
「PDF获取 → 精读≤8篇 → 撰写综述artifact」三个环节均无任何执行记录，我不会在未读文献的情况下编造综述内容。
```

**根因**：`literature_pipeline.ts:499` 的 `renderDigest()` 把「综述：artifact …」写在**最后**，
而整个 digest 最后一行是 `return lines.join("\n").slice(0, 1500);`。
5–6 条查询 × 8 个源的每源状态行先把 1500 字符吃光 → 综述行、预筛行、失败行**全部被切掉**。
交给总结阶段的执行日志里因此真的没有综述的痕迹，模型按「不许编造」的约束如实报告没有——**模型是对的，喂给它的材料是错的**。

三次复现口径一致：

```
a9-lit-1 digestLen 1500  digest 含「综述：artifact」? False
a9-lit-2 digestLen 1500  digest 含「综述：artifact」? False
a9-lit-3 digestLen 1500  digest 含「综述：artifact」? False
```

这与 v0.10.0-alpha.1 修掉的 U57（「skill 摘要被 600 字符上限切掉」）是**同一个形状换了一个上限**。

## 3.2 U72（高）· chat 路径硬编码 quick 档
