## 3. 三件套各自的科学判据（checklist 第 5 条：断言不是「跑完没报错」）

数据集全部**离线生成/离线拷贝**，测试期零网络。生成脚本随 fixture 一起进仓库
（`tests/fixtures/<id>/generate.py`），固定 seed，重跑逐字节一致。

### 3.1 scanpy（`tests/unit/scanpy_e2e.test.ts`）

数据集：240 细胞 × 120 基因，三种细胞类型各带 5 个专属 marker（`MARKA*` / `MARKB*` / `MARKG*`）。

- **每组 5 个 marker 必须整组落在某一个 cluster 的 top-5 里，且三组落在三个不同 cluster**
  （实测：cluster 0 = MARKA 全五个、cluster 1 = MARKB、cluster 2 = MARKG）
- 聚类数 = 3；与真实标签的纯度 ≥ 95%（实测 100%）
- `clusters.csv` 与 `embedding.csv` 的簇号逐细胞自洽

### 3.2 pydeseq2（`tests/unit/pydeseq2_e2e.test.ts`）

数据集：12 样本（6 对照 / 6 处理）× 300 基因，15 个上调 5 倍、15 个下调 5 倍、270 个噪声。

- **15 个 UP 基因全部 padj < 0.05 且 log2FC > 1**（实测最小 log2FC = 1.80，理论值 log2(5)=2.32）
- **15 个 DOWN 基因全部 padj < 0.05 且 log2FC < −1**（实测最大 = −2.00）
- **噪声基因假阳性率 < 5%**（实测 4/270 = 1.5%）——只测灵敏度不测特异性等于没测
- size factor 每样本一条且全为正

### 3.3 cobrapy（`tests/unit/cobrapy_e2e.test.ts`）

模型：e_coli_core（cobrapy 自带的教科书模型，解压成 `tests/fixtures/cobrapy/e_coli_core.xml`）。
四个判据都是**公开定值**：

- 有氧最大生长率 = **0.873922 h⁻¹**
- 厌氧（`EX_o2_e` 下界置 0）= **0.211663 h⁻¹**
- 敲掉 eno（`b2779`，烯醇化酶）→ 生长归零（糖酵解断了）
- 敲掉 nuoA（`b2280`，NADH 脱氢酶）→ **掉到厌氧那个值**：呼吸链没了只能发酵。
  这条最值钱——两条互相独立的路径必须给出同一个数，不是「跑完没报错」。

## 4. 两条设计决定（任务书点名的两处，写清楚为什么）

### 4.1 探测与真跑是**同一条路径**（对着 V27 那个形状修）

反面教材在仓库里：`doctor.ts` 的 `probeCode()` 是一段内联 python，**探测根本不摸 runner.py**。
于是 runner 没解包出来时探测照样报「可用」，直到 submit 才 ENOENT。

三件套的 `probeCode()` 改成：用 `importlib.util.spec_from_file_location(...)` 加载
**`entryPointFor()` 返回的那个文件本身** → `exec_module()`（执行 runner 的模块级
`import scanpy` / `import pydeseq2` / `import cobra`）→ 调它的 `probe()`。
生成器是 `backend/src/simulation/scanpy/probe.ts` 的 `probeCodeFor()`，三个平台共用。

于是这三种坏法在探测阶段就红，且都带安装命令：runner 没解包出来 / 包树缺件 / 依赖没装。
门禁两条（每个平台各一份）：
① `probeCode()` 里必须字面包含 `entryPointFor()` 的绝对路径 + `exec_module`；
② 把 `entryPointFor()` 指到一个不存在的文件 → `available()` 必须 `ok:false`，
且 `submit()` 在同一条路径上抛 `runner 脚本不存在`——两边结论一致才叫「同一条路径」。

`cobrapy` 还多守一条：`import cobra` 成功 **≠** 有 LP 求解器。`probe()` 把 optlang 认得的
求解器列出来，一个都没有就算不可用。

### 4.2 `deterministic` 是**测出来的**，不是声明的

三个平台实测都是「同一 spec 两次跑出的产出逐字节一致」，所以三个都标 `deterministic = true`。
但这个结论不写在注释里就完了——每个 e2e 里有一条：

```
跑两遍 → 比全部产出文件的字节 → expect(逐字节一致).toBe(platform.deterministic)
```

**双向断言**：标成 true 但实测不一致会红，标成 false 但实测一致也会红。

为此 scanpy 的产出里刻意加了第三份 `embedding.csv`（降维坐标）。理由见 §5 阴性对照 ④：
PCA 换成无种子的 randomized solver 之后，`clusters.csv` 与 `markers.csv`
**一个字节都不会变**（数据太可分），只有降维坐标会变——没有这份产出，
「非确定性被报成确定性」这条阴性对照根本红不了。

需要说清的边界（SKILL.md 里也写了）：这三个 `true` 保证的是**同一台机器上重跑**逐位一致
（runner 把 `sc.settings.n_jobs` / `DefaultInference(n_cpus=...)` 钉成 1，PCA 用 arpack + 固定种子，
leiden 传 `random_state`，cobrapy 默认再跑一次 pFBA 收敛 alternate optima），
**不保证跨机器 / 跨 BLAS 版本 / 换 LP 求解器**。

## 9. 没做完 / 刻意没做的（如实列）

三个平台**都做完了**，没有半成品。但每个平台的能力面都是**窄的**，SKILL.md 里各有一段
「本平台目前的边界」写死，免得 agent 在报告里想象没有的功能：

- **scanpy**：只吃 CSV 计数矩阵，**不读 h5ad / 10X mtx**；**没有线粒体比例 QC**
  （staged 设计里的 `maxPctMt` 没实现——加它需要一份带 MT 基因的 fixture，
  「声明了却从没被跑过的参数」正是本仓库门禁最恨的形状，所以宁可不加）；
  没有批次校正、没有细胞类型自动注释。
- **pydeseq2**：只支持**单因子两水平**对比（`~<designFactor>`）。多因子设计
  （`~batch + condition`，staged 设计里有）、连续协变量、LFC shrinkage、火山图渲染都没做。
- **cobrapy**：单目标 FBA / pFBA / FVA。没有 OptKnock 类菌株设计、没有动力学/时序模拟、
  没有通量采样（flux sampling）、不做多组学整合。

与 staged 设计的两处**有意偏离**（staged 是设计稿，实现以实测为准）：

1. staged 的 `scanpy/SKILL.md` 写 `deterministic: false`（按 openmm 的保守类比推的）。
   实测**逐字节可复现**（n_jobs=1 + arpack + 固定种子），所以标 `true`，
   并且有一条每次都重测的门禁兜着。staged 的 `pydeseq2/SKILL.md` 本来就写了
   「除非实现阶段实测证明单线程下逐位稳定，才升级为 deterministic: true」——照做了。
2. kind 名与参数名按实现落地：`sc-cluster` / `bulk-de` / `fba`
   （staged 写的是 `scrna-standard-pipeline` / `bulk-rnaseq-deseq2`），
   参数是 `countsPath` / `metadataPath` / `modelPath` 而不是 staged 的 `inputPath` / `countsFile`。

## 10. 遗留问题

1. **`doctor.ts` 的 `probeCode()` 还是 V27 那个形状**（内联 python，不摸 runner）。
   本 lane 没有它的所有权，没动。三件套已经证明修法可行且门禁写得出来——
   建议收口或下一波把 `doctor` 一并改成同一套（`probeCodeFor` 直接可复用）。
2. **`pyref` / `openmm` 的探测也还是内联形状**。同上，不在本 lane 授权范围内。
   openmm 的探测至少 import 了真包，比 doctor 好，但仍然不摸 `runner.py`。
3. **二进制模式下「没装依赖」的报错点名的是 numpy 而不是平台自己的包**（见 §6.1）。
   要更精确的话，可以让 runner 把重依赖 import 挪进 `probe()` 里逐个 try——
   但那会让 runner 的模块级 import 与探测走的 import 分家，正好违反 §4.1 的判据。
   现状（第一个缺失的依赖 + 完整安装命令）是可操作的，先这样。
4. **`tests/fixtures/cobrapy/e_coli_core.xml` 是 351 KB 的 SBML 文本**（cobrapy 包里那份
   `textbook.xml.gz` 解压出来的）。选文本不选 18 KB 的 `.gz` 是为了可审计（二进制进仓库
   审起来是黑盒），但它是本仓库最大的一份 fixture。收口若嫌大，换成 `.gz` 只需改
   fixture 与两处路径常量——runner 的 `load_model` 已经认 `.xml.gz`。
5. **契约测试把 unit 套件拖长了约 35 秒**（scanpy 一家占大头：每条完整算例约 6 s，
   冷启动首轮因 numba JIT 约 15 s）。真跑是这条 lane 的意义所在（VALIDATION_PLAN 禁止
   下载、也不能只做形状断言），但如果 CI 时间成为问题，可考虑把 scanpy 的合成数据集
   从 240×120 再砍一半。
6. **`markers.csv` 的 `padj` 直接来自 `rank_genes_groups`，没有做跨 cluster 的多重比较校正**。
   scanpy 上游就是这个口径，SKILL.md 里提醒了「统计显著 ≠ 生物学意义」，
   但如果下游要拿它做结论卡，值得再想一层。
