# G8-2 · V101 扩展 trust 指纹改为目录清单

**日期** 2026-09-11 · **分支** `fix/G2-V101-trust-fingerprint` · **闸门** G-2

## 问题
`checkTrust` 只对 `entryPath`（TS 扩展的 `index.ts`）取 sha256。扩展目录里任何被入口 `import` 的 helper 文件改了内容，指纹不变，`--trust` 的记录继续生效——攻击面：替换 helper 即可绕过 trust 门。

## 改动
- `backend/src/extensions/fingerprint.ts`
  - `TrustRecord.scheme?: "file" | "dir-manifest-v1"`；`FingerprintTarget = {kind:"file"} | {kind:"dir"}`。
  - `dirManifest(dir)`：排序遍历，跳过 `node_modules/` `.git/` 点文件与符号链接；每项 `relpath\tsha256`。`sha256Dir` 对清单再取 sha256。
  - `checkTrust(name, target, requestTrust, options)`：`changed = 内容哈希变 || scheme 变`（旧的 `file` 记录对目录扩展视为变化，需重新 `--trust` 一次——有意为之，升级即重校）。
- `backend/src/extensions/loader.ts`：TS 扩展改为 `{kind:"dir", path: extensionDir}`；mcp_client 仍按 `mcp.json` 单文件。
- 顺手修 G-1 测试 tsc 错误（`fx.close?.()` 不存在）。

## 测试
- `tests/unit/v101_trust_dir_fingerprint.test.ts` 4 条：
  1. 同内容不同顺序写入 → 清单相同；2. 改 helper → 指纹变；3. `checkTrust` 旧 `file` scheme 记录 → 需重 trust；4. **装载层**：`good-skill` 拷到临时目录 `trust` 装载 → 再装载通过 → 写入 `helper.ts`（入口未动）→ 不带 trust 拒绝且原因含"已变化" → 重 `--trust` 通过。
- **阴性对照**：loader 改回 `{kind:"file", path: entryPath}` → 测试 4 红（3 pass / 1 fail）；还原 → 4/4。
- 现有 extension 测试 66/66；unit 全量 2281；typecheck clean。
