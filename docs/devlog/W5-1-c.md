## 交付了什么

一条从核心实现到前端渲染的完整竖切：

- **`backend/src/chem/depict.py`**（新建）：stdin JSON `{smiles, width?, height?}` →
  stdout JSON。成功：`{ok:true, svg, canonicalSmiles, formula, molWeight, rdkitVersion}`；
  失败：`{ok:false, error:{kind, message}}`，`kind` ∈
  `invalid_smiles | rdkit_unavailable | bad_output`（`timeout` 是 `depict.ts` 在子进程
  超时被 kill 时自己判定的，不是 `depict.py` 自己吐出来的）。
  - rdkit 输出自带 `<?xml ...?>` 前缀，在这里统一裁掉（`svg[svg.find("<svg"):]`），
    不是把 `assertSafeSvg` 的规则放宽去迁就它。
  - `RDLogger.DisableLog("rdApp.*")` 关掉 rdkit 对非法 SMILES 的 C++ 层噪音日志，
    自己给结构化错误 + 下一步指引（元素符号/化合价/环闭合编号/括号）。
- **`backend/src/chem/depict.ts`**（新建）：`depictSmiles(input, deps)`——子进程
  （复用 `simulation/platform.ts` 的 `resolvePython()`，不重开一份口径，异议 X-5）+
  超时（默认 15s，`Bun.spawn` + `setTimeout` kill）+ `assertSafeSvg()`（第二道防线：
  以 `<svg` 开头、无 `<script>`、无 `on*=` 事件属性、无 `<foreignObject>`）+
  `ArtifactStore.save()`（先写一个 OS `mkdtemp` 临时目录，`save()` 拷贝进真实
  storageDir 后立即 `rmSync` 清理）+ `records.createFromArtifact({evidence:"computed",
  metadata.kind:"chem_depiction"})`。非法输入/任何失败分支**不落任何 artifact/record**。
  - 没给 `name` 时用 canonical SMILES 的短 hash 当默认文件名——重复 depict 同一个分子
    稳定落到同一个 artifact 并递增版本号，不同分子各自成一条 lineage（单测覆盖）。
- **`backend/src/chem/cli.ts`**（新建）：`runChemCommand(args, deps)` ——
  `spark-research chem depict "<SMILES>" [--name mol] [--width W] [--height H] [--json]`。
  风格与 `proteins/cli.ts` 一致：退出码 + 注入 out/err，`python`/`timeoutMs` 可注入
  （测试用桩解释器，不需要真的卸载 rdkit）。**这个 handler 本身完全独立于
  `index.ts`**，`tests/unit/chem_cli.test.ts` 直接调用它验证，不经过 CLI 主入口。
- **`backend/src/server/routes/chem.ts`**（新建）：`POST /api/chem/depict`。风格与
  `proteins.ts` 一致——解析 → 调用 → 序列化。失败用 422（调用方的错，不是服务端故障，
  `detail.kind` 带原始错误分类）。
- **`backend/src/server/app.ts`**：加一行 import + 一行 `app.route("/api/chem",
  chemRoutes(ctx))`（紧邻 `proteinRoutes` 那一行）。
- **`backend/src/mcp/tools.ts`**：追加 `chem_depict` 一条，描述按文件头「判断二」四段式
  写（【何时调】【参数示例】【何时不该用】【典型链路】+ 额外补了【常见错误】）。
- **`frontend/workspace/src/components/center.tsx`**：`ArtifactsView` 的打开面板加一个
  `contentType === "image/svg+xml"` 分支，`<img src={"data:image/svg+xml;utf8," +
  encodeURIComponent(body)} />`（不 `innerHTML`——SVG 里混入 `<script>` 也不会执行，这是
  后端 `assertSafeSvg` 之外的第二道防线，AD-7：不引入前端依赖）。`content` 信号加了
  `contentType` 字段（`ArtifactVersion` 类型本来就有这个字段，`frontend/workspace/

### ⑤ 子进程超时测试的一个环境陷阱（仅记录，不是生产代码问题）

写 `tests/unit/chem_depict.test.ts` 的超时用例时，第一版桩解释器用
`cat > /dev/null; sleep 5`（两条独立语句）在 `timeoutMs=200` 下实测要等满 5 秒才
返回——不是 `proc.kill()` 没生效，而是 `sleep` 作为独立语句会被 shell fork
成**子进程**，`kill()` 杀掉的是外层 `sh`，孤儿 `sleep` 进程还留着继承来的 stdout
管道 fd 不放，`new Response(proc.stdout).text()` 就要等那个孤儿进程 5 秒后自然退出
才能读到 EOF。换成 `exec sleep 5`（`exec` 让 sleep 替换掉当前进程、不 fork、同一个
pid）之后 kill 立即生效（202ms 左右）。这只是**测试桩脚本**的写法问题——生产的
`depict.py` 是单一 rdkit 脚本，不会 fork 子进程，不存在这个风险，记在这里是为了
以后其它 lane 写类似的子进程超时测试时不用重新踩一次。
