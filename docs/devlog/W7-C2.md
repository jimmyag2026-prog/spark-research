# W7-C2 · 长任务 liveness（BACKLOG V70 + V3）

> worktree `~/Desktop/AI4S/spark-research-C2`，分支 `feat/W7-C2-liveness`。

## 问题

- **V70**：`server/tasks.ts` 的僵尸任务判据（V11 的 `recovered` 标记）只回答「这条记录是不是从磁盘读回来的」，从不回答「持有它 `run()` 闭包的进程现在到底还在不在」——kill 掉那个进程之后，`lit tasks` 会永久显示 `running`，没有 liveness 判据。
- **V3**：仿真 poll（`simulation/platform.ts` 的 `SubprocessSimulationPlatform.poll()`）只核 `isProcessAlive(record.pid)`，pid 会被系统回收又分配给一个完全无关的新进程（pid 复用），旧代码没有交叉核验，会把「pid 复用」误判成「还在跑」。

## 与任务书的偏差（如实）

1. **仿真侧「pid 不存在」没有并入 orphaned**（V3 原文里 `pid 不存在，或存在但启动时间对不上 → orphaned` 的前半句）。`platform.ts` `poll()` 里 `!isProcessAlive(record.pid)` 的既有分支保持原样：`state: "failed", recoverable: true, message: "...已消失..."`。原因：这条分支已经被 `tests/unit/experiment.test.ts`（L472-482）与 `tests/unit/experiment_e2e.test.ts`（L164-181，"kill-lost" 用例）的既有断言锁定（`process.kill(pid,'SIGKILL')` 之后期待 `lastError` 含"已消失"、`recoverable===true`），且这两个文件不在本 lane 允许改动的测试文件列表内（只有 `tests/unit/*task*.test.ts` 允许更新期望），`experiment/loop.ts`（读 `status.state` 决定 `marked_failed`/`still_running`）又是明确禁止修改的文件。把这条分支也改成 `orphaned` 会让 `loop.ts` 把它归到 `marked_failed` 分支之外的未知状态（`resume()` 的 `if (status.state==="running"||"pending") ... else if (status.state==="completed") ... else marked_failed`——`orphaned` 会落进 `else`，其实行为上等价于现在的 `failed`，但 `lastError` 文案与 `recoverable` 语义会变，直接冲掉两个文件的断言）。V3 真正的投诉是"pid 复用误判"——那半句（`!handle` 分支）已经完整实现；"pid 干脆不存在了"这半句本来就没有复用歧义，不存在就是不存在，沿用既有口径风险最小。**需要收口处理时**：把 `poll()` 里那条 `!isProcessAlive` 分支的 `state` 也改成 `orphaned`，同步改 `tests/unit/experiment.test.ts:481` 与 `tests/unit/experiment_e2e.test.ts:181` 的 `toContain("已消失")` 断言（文案不必变，只是 state 名字变了，`loop.ts` 的 `resume()`/`resumeCompute()` 需要确认 `orphaned` 落进哪个 action 分支是符合期望的语义）。

## 调试中撞到的坑（值得记一笔，免得下次重踩）

`ps -o lstart=` 的输出不带时区（如 `"Fri Sep 11 14:17:56 2026"`）。用 `new Date(那个字符串)` 直接解析这种非 ISO 格式，"要不要按本地时区补全"是 JS 引擎的实现细节——实测**同一台机器上两个不同的 bun 进程调用同一段代码、查同一个 pid，会给出相差 8 小时的结果**（一个按本地时区补全、一个直接当 UTC 吃）。这直接把 `tests/unit/experiment_e2e.test.ts` 的「编排进程被 SIGKILL，仿真任务活着」用例打红：driver 子进程记录的 `pidStartedAt` 与主测试进程重新查询的 `currentStartedAt` 因为这个解析歧义對不上，被误判成 `orphaned`（本该是 `still_running`）。

修法：调 `ps` 时显式传 `env: { ...process.env, TZ: "UTC" }`（`ps` 认这个环境变量，会把 `lstart` 按 UTC 打印），拿到字符串后再手工追加 `" UTC"` 消歧义再喂给 `new Date()`。修完之后 `tests/unit/experiment_e2e.test.ts` 与 `tests/unit/experiment.test.ts` 的全部既有用例（含两个真实 `SIGKILL` 场景）都保持绿。
