# W5-1 δ · V25「安全门字段兑现」——concentration_limit / biosafety 从恒空转变成真消费

lane：`W5-1 δ`（W5-1，附线 δ）· 分支：`feat/W5-1-d` · 设计真源：`docs/DEVELOPMENT_PLAN_v0.5_MODULES.md` §1.5 表格第一行

## 背景

`lab/safety.ts` 的四条湿实验安全门规则里，`concentration_limit` 与 `biosafety` 从
v0.3（D-8 口径收敛）起就**在自然语言主管线上永远空转**——规则本身是对的（`evaluate()`
正确读取 `ReagentSpec.concentration` / `ProtocolStep.params.biosafetyLevel`），但
协议编译器（`lab/protocol.ts`）从来不产生这两个字段，兜底只有 `unconsumedWarnings`
强制告警。这是对接物理设备的硬前置：在这两条规则真的能拿到输入之前，「有安全门」这个
说法不成立。

## 做了什么

**`backend/src/lab/protocol.ts`**：
- 新增 `extractConcentration(sentence)`：解析 `10%` / `5mol/L` / `5mM` / `浓度为500`
  等写法，抠不出数字就返回 `undefined`（`摩尔浓度`这种无数字的写法结构性地抠不出来，
  是合法的解析失败，不是 bug）。
- 新增 `extractBiosafetyLevel(sentence)`：解析 `BSL-3` / `生物安全二级` /
  `biosafety level 2` 等写法。
- 编译主循环：
  - 浓度**只在同一子句里恰好点名一种试剂时**才把值写进那个 `ReagentSpec.concentration`
    ——同句出现两种及以上试剂时，浓度归谁没法从句法上确定，不瞎猜，走未消费分支。
  - 生物安全等级挂到「这句话最终归属的步骤」——本句新建的步骤，或它作为续句合并
    进的上一步（与温度/时长续句同一套归属逻辑）；没有步骤可挂（既不新建、也不能
    合并）时走未消费分支。
  - `scanUnconsumedSignals()` 加了 `consumed: { concentration, biosafety }` 参数：
    只在信号存在**且**没有被真正写入编译产物时才报，解析/归属成功的不再报。
- 更新了 `Protocol.warnings` 与信号扫描区的头部注释，把「主管线完全不解析」的旧口径
  改成「会尝试解析，解析/归属成功才消费」。

**`backend/src/lab/safety.ts`**：
- 规则本身**没有功能改动**——它们从 D-8 起就是对的，问题一直在生产者侧。
- 重写了文件顶部的口径注释，把「concentration_limit / biosafety 永远空转」改成
  「部分消费，边界写清楚」（同句单一试剂 / 归属得到步骤才生效；跨句归属仍不认）。

**测试**：
- `tests/unit/lab_compile.test.ts`：把断言「浓度/生物安全描述始终报未消费」的两条
  旧测试改写成六条——覆盖「同句单一试剂 → 消费成功」「同句多试剂 → 归属歧义仍报」
  「浓度无试剂可挂 → 仍报」「同句 biosafety → 消费成功」「续句 biosafety → 消费成功」
  「独立 biosafety 无步骤可挂 → 仍报」。

  fail、「在BSL-3环境下加入50uL样品」触发 `biosafety` fail，并且都断言
  `protocol.warnings` 为空（解析成功即消费）。

**collateral（越出严格文件所有权，见下方说明）**：

## 安全门改完之后的真实覆盖范围（如实写，不夸大）

- `volume_capacity`：全程接编译产物核对，未变。
- `chemical_compatibility`：有限中英文/分子式试剂词表，未变。
- `concentration_limit`：**从恒空转变成部分消费**。触发条件——浓度描述与被限制的
  试剂名出现在**同一个分句**里，且该分句只点名了**恰好一种**试剂。同句多种试剂
  （归属歧义）、或浓度描述与试剂名分处不同分句（跨句归属，例如「配制次氯酸钠，
  浓度为10%」——这其实是自然语言里更常见的写法），这条规则**仍然空转**，仍靠
  `unconsumedWarnings` 兜底。
- `biosafety`：**从恒空转变成部分消费**。触发条件——生物安全等级描述能归属到
  「本句新建的步骤」或「它作为续句合并进的上一步」。一句独立的生物安全描述、
  前面没有任何步骤可挂（例如整份协议只有这一句话）时，**仍然空转**。
- `unconsumedWarnings`：口径从「浓度/生物安全信号出现就一定报」改成「解析失败或
  归属不了才报」——这是本次改动里唯一从「总是」变成「有条件」的分支，三条阴性
  对照里①专门验证了这个反转没有把「真消费」和「告警熄灭」这两件事拆开。

**诚实的结论**：这次改动把两条规则从「无论怎么写协议都拿不到输入」收窄到「按最常见
的『先说试剂后说浓度』分两句写就还是拿不到输入，只有把两者写进同一句才生效」。
跨句归属没有做——那需要在子句之间维护「最近提到的试剂」这类状态，复杂度和误判面
（浓度到底该归给哪一句提到的哪个试剂）都明显上升，不是这条 lane 的范围。物理设备
对接的门槛（README 里写的那句）目前的判断是：**这个新边界仍然不够**，因为跨句
写法在真实协议里更常见，不建议把这次改动当成「biosafety/concentration 已经可信」
的信号去解除 Opentrons 对接的门槛。

## 遗留问题

1. **跨句归属未做**：「先说试剂、后单独一句说浓度/生物安全等级」是自然语言里更
   常见的写法，两条规则目前都不认，仍然只靠 `unconsumedWarnings` 兜底可见。
2. **多试剂同句时的浓度完全不做归属尝试**（宁可保守报未消费也不猜），如果未来要
   补，需要想清楚「猜错了归给了错的试剂」比「不猜」更危险还是更安全——这次判断是
   更危险，所以没做。
3. `extractConcentration` 的单位目前不区分 `%`/`mol/L`/`mM`——直接把数字量级喂给
   `MAX_CONCENTRATION`（该表本身单位含义也不明确，是历史遗留，D-8 就没改）。真实
   化学场景里 10% 和 10 mol/L 完全不是一个数量级，这次沿用了旧表的隐含假设，没有
   重新设计单位换算，因为那超出了「兑现字段」这个范围。
4. `tests/unit/wet_loop.test.ts` 与 `tests/unit/server_lab.test.ts` 各改了一条测试
   （见上方「collateral」说明）——严格按文件所有权算是越界，但不改会导致基线测试
   永久变红，且改动是 V25 行为变化的直接后果，判断后动了，如实记录在此。
