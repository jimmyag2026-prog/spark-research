所以 `SEMANTIC_THRESHOLDS` 留空，novelty 的评级判据仍然走词面（K-4）。**

## 一、开工第一件事：Ollama 的 `/v1/embeddings` 核过了

§1.2.1 要求 lane β 开工先在本机 Ollama 上核一次 OpenAI 兼容端点，核不过就加
`ollama_native.ts`。**核过了，所以不需要那个文件。**

```
$ curl -s -X POST http://localhost:11434/v1/embeddings \
    -H "Content-Type: application/json" \
    -d '{"model":"nomic-embed-text","input":["hello world","protein folding prediction"]}'
HTTP 200
top keys: ['object', 'data', 'model', 'usage']
object: list
n: 2
dims: [768, 768]
usage: {'prompt_tokens': 5, 'total_tokens': 5}
```

（ollama 0.12.10。形状与 OpenAI 规范一致：`data[i].embedding` + `usage.prompt_tokens`。）

**但踩到一个没写在规划里的坑**：Ollama 的批大小限制是**按 token 总量**算的，不是按条数。
一次塞 4 条 1000+ 字符的「标题+摘要」，模型 runner 进程会直接死掉：

```
HTTP 500: {"error":{"message":"do embedding request: Post \"http://127.0.0.1:53308/embedding\": EOF", ...}}
```

单条发同样的文本没问题，说明不是长度上限而是批总量。只卡 `batchLimit` 条数挡不住，
所以 `EmbeddingRouter` 改成**条数上限 + 字符预算**双约束分批
（`chunkByCharBudget`，`EMBED_BATCH_CHARS = 3000`），单条超预算时单独成一批、
**绝不截断文本**（截断会悄悄改变语义，标定就白做了）。加上之后 149 条文本全量录制零失败。

顺带记一条：适配器把这个 500 如实报成了 `upstream` 失败而不是吞掉——AD-13 在真实故障上验过了一次。

## 二、模块设计（§1.2.1 / §2.8）

按 §2.8 的签名实现，没有自己改设计。几处值得记的决定：

### 2.1 `cosine` 的两条刻意规定

- **维度不一致抛异常**。不同模型的向量混算出来的数没有意义，静默返回会一路流进阈值判定。
- **零向量返回 0，不返回 1、也不返回 NaN**。零向量方向未定义；把「未定义」解释成
  「完全相似」是最危险的沉默失败（provider 故障吐全零 → 全判成相似 → 所有 claim 都成 existing）。
  返回 0 让故障在标定测试上当场可见——这正是阴性对照②验的东西。

### 2.2 embedding provider 表与 chat 的 ADAPTERS **刻意分开**

「能聊天」不蕴含「能算向量」：anthropic 至今没有 embedding API，deepseek / openrouter
也不提供 `/v1/embeddings`。把 chat 的 provider 列表拿来当 embedding 列表，等于对着
一个不存在的端点发请求再把 404 解释成「模型不支持」。所以只登记确实有该端点的
（`local` / `openai` / `qwen`），其余走可见的 `unsupported` 并写明支持哪几个。

凭据环境变量仍从**真源派生**（`PROVIDER_API_KEY_ENV` ← chat router 的 ADAPTERS），不手抄第二份。

**已核实程度（如实）**：`local`（Ollama 兼容层）本机实测过；`openai` / `qwen` 两条按各自
公开文档的兼容端点写，**本 lane 没有 key、未实测**，也因此不会给它们登记任何阈值。

### 2.3 走 `HttpClient` 而不是裸 fetch

chat 侧走 `fetchImpl`，embedding 这边走 `http/client.ts` 的 `HttpClient`——
只有这样 `http/fixture.ts` 的录制回放才零改动可用，CI 才不依赖网络。
副作用是安全的：FixtureHttp **请求头永远不落盘**，凭据结构上进不了 fixture（已核，见第六节）。

## 三、标定：方法、数据、结论

### 3.1 标定的是「管线真正使用的那个量」

不是一个更好看但没人用的统计量：

```
semanticAffinity(claim, paper)
  = max over [claim.statement, ...claim.queries] of cosine(embed(text), embed(paperEmbedText(paper)))
```

取 max 的理由与 `affinity.ts` 的 `claimAffinity()` 同源（中文陈述对英文论文的余弦天然偏低，
取平均会把命中的英文检索式抹平），与 `novelty.ts` 的 `applySemanticAffinity()` 逐字同构。

> **对 §1.2.3 schema 的一处扩展**：规划里的条目是
> `{ claim, lang, expected, positives, negatives, cassette }`，没有 `queries`。
> 我给每条 claim 补了 2 条英文检索式——因为管线算的就是「陈述 + 各检索式」上的 max，
> 只标定陈述会标出一个**没人用的量**。补之前 e01 这类中文 claim 对英文原文只有 0.461，
> 补之后 0.579：差的那一截正是管线真实拥有、而标定却看不见的信息。

### 3.2 样本从哪来（§1.2.3 的三个来源都用了）

| 来源 | 条数 | 做法 |
|---|---|---|
| 已发表（existing） | 17 | 从 `tests/fixtures/literature/{search-alphafold,novelty-check}.json` 里真实录制的响应播出论文，每篇写一条**改述** claim（不抄标题、换措辞换语序、中英各半）。正样本 = 该论文，负样本 = 同磁带同领域的 3 篇邻近工作 |
| 杜撰组合（novel） | 13 | 把两个不相干的方法/对象拼成一条 claim。最近邻从**全部 59 篇**里取 |
| P4 原有 2 条 | 2 | `PUBLISHED_CLAIM` / `FABRICATED_CLAIM` 原样保留（h01/h02），作历史对照 |

落盘 `tests/fixtures/novelty/calibration.json`（30 条 claim + 59 篇论文语料）。
向量走 `FixtureHttp` 录制到 `tests/fixtures/embeddings/local-bge-m3.json`，CI 回放零网络。

**样本撰写的三条纪律**（第一轮测完发现自己违反了，改了一次，写下来免得下次重犯）：
- R-A：existing claim 必须指到该论文**区别于自己负样本**的那处贡献；
- R-B：负样本不许是正样本的**近重复贡献**（例如 RoseTTAFold 之于 AlphaFold2 是并列的同一件事，
  拿它当负样本等于把 ground truth 标错）；
- R-C：杜撰 claim（**以及它的检索式**）不许照抄语料里某篇论文的标题名词短语——
  否则量的是「抄没抄标题」，不是「是不是同一件事」。

### 3.3 选模型：nomic-embed-text 出局，bge-m3 入选

首选 `openai/text-embedding-3-small` 需要 `OPENAI_API_KEY`，**用户没有**，所以走 §1.2.3 的
备选路线：本机 Ollama。

先试 `nomic-embed-text`（规划里点名的那个），**当场出局**——它是英文中心的，
中英文 claim 落在完全不同的两个区间里，一个全局阈值根本无从谈起：

```
MODEL=nomic-embed-text
  英文 claim 的正样本： 0.745 … 0.861
  中文 claim 的正样本： 0.364 … 0.522        ← 与英文差了整整一个区间
  minPositive = 0.3644   maxNegative = 0.7846
```

换 `bge-m3`（多语言）之后中英同尺度，这才谈得上标定。**记一条**：跨语言 claim 是这个仓库的
常态（claim 提取 prompt 明确要求中文陈述 + 英文检索式），embedding 模型**必须是多语言的**，
否则语义化从第一步就不成立。

### 3.4 实测分布（bge-m3，2026-09-10，59 篇语料）

| | 语义（bge-m3） | 词面（内容词覆盖率） |
|---|---|---|
| 正样本区间 | 0.579 … 0.746 | 0.714 … 1.000 |
| 最高负样本 | 0.660 | 0.857 |
| 最优阈值区间 / 错分 | [0.64, 0.66] → **3/47** | [0.67, 0.71] → **1/47** |
| 各自生产阈值上的错分 | 0.665（零假阳性点）→ **4/47** | 0.75 → **2/47**（假阴 1 / 假阳 1） |
| 零假阳性的最低阈值 | 0.665（此时假阴 4） | 0.86（此时假阴 4） |

### 3.5 与 §1.2.3 的偏离：「两侧余量各 ≥0.05」这个条件无解

§1.2.3 要求断言阈值落在最高负样本与最低正样本之间、两侧余量各 ≥ 0.05。
**在这份样本上，两种口径都无解**——正负分布本来就重叠（语义 0.579 < 0.660，
词面 0.714 < 0.857）。「就是这件事」与「同一个领域的邻近工作」之间本来就有一段连续过渡带。

照做不了，就换成在真实分布上可达成、且负性更强的一套判据（`novelty_calibration.test.ts`）：

1. 样本量与构成满足 §1.2.3 下限，`sampleSize` 与 calibration.json 条数对撞；
2. 分布数值逐个钉死（换模型 / 换文本规则 / 换语料都会红）；
3. **零假阳性**是硬约束（理由见 3.6）；
4. 最优阈值区间与错分数钉死，阈值挪 ±0.1 判据即不成立；
5. 与词面口径在**同一份样本、同一个取法**下逐维度对照；
6. 「将来若有人登记阈值」的守门用例：必须零假阳性 + 落在最优区间 + 样本数对得上 + **赢过词面**。

**没有擅自改设计文档**（纪律要求），偏离只写在这里与 `calibration.ts` 顶部。

### 3.6 为什么把「零假阳性」定为硬约束

确定性层的两条规则对两类错误**不对称**：

- **假阳性**（把邻近工作当成「就是这件事」）→ R5 会把一条本来正确的 novel 升级成 existing。
  那是确定性层**凭空造出**一条不存在的「已有工作」，等于用一个错误的判据去压真实的新想法。
- **假阴性** → R5 少抓一次、R4 多降一级，方向都是**更保守**，不会让模型的结论被放行得更松。

宁可漏，不可错认。所以候选阈值先过零假阳性这关。

### 3.7 结论：没赢，所以不登记

逐维度对照下来，语义**没有一个维度稳定胜出**：最优错分 3 vs 1，各自生产阈值上 4 vs 2，
零假阳性点上的假阴数打平（4 vs 4）。n=47 且词面分数高度量化（0.667 / 0.75 / 0.857 / 1.0），
这点差距本身也在噪声量级内——所以正确的结论不是「语义略差」，而是
**「没有证据表明语义更好」**，那就不该换判据。

语义唯一确实修掉的一类错：词面把**用词高度重合的邻近工作**判成「就是这件事」
（h01 的负样本词面 0.857 ≥ 0.75 → 假阳性；语义只给 0.615）——正是 `novelty.ts` 里
早就预警过的那个失效模式。但语义自己有对称的一类错（见下一节）。

**顺带量出一件事**：词面的 0.75 是 P4 在**2 条样本**上标的。样本一多，它连自己的
最优区间 [0.67, 0.71] 都不在。这不是本 lane 的所有权范围（改它要重跑整条 P4 叙事），
**登记为遗留问题**，见第七节。

## 四、语料分布的教训（比阈值本身更值得记）

**第一版标定语料只收了「有摘要」的 40 篇，把 19 篇没摘要的排除了。**
阈值因此标在 0.645，`novelty_calibration.test.ts` 全绿，`embeddings.test.ts` 全绿。

然后 e2e 当场打脸。杜撰组合 claim（h02 那条，本该保持 novel）被误升级成 existing：

```
DBG sem=0.660 lex=0.333 abs=   0  Understanding Protein Dynamics Using Conformational Ensembles
DBG sem=0.571 lex=0.400 abs=   0  Pressure and Temperature Phase Diagram for LiquidLiquid Phase Separation...
DBG sem=0.562 lex=0.444 abs=1268  Biophysics-based protein language models for protein engineering
DBG sem=0.532 lex=0.556 abs= 621  Modeling Boltzmann-weighted structural ensembles of proteins using AI...
```

排第一的那篇 **abs=0**——没有摘要，嵌入文本退化成只剩标题。而**裸标题是一句没有背景
稀释的高密度主题陈述，分数系统性偏高**：0.660 一下把 0.645 顶穿。管线在真实检索里
就是会遇到这类条目（同一份 novelty-check 磁带里 59 篇有 19 篇没摘要，占三分之一），
而我的标定语料把它们全筛掉了。

**用一个比生产更干净的语料标定出来的阈值，在生产上必然偏，而且偏的方向不可预测。**
这正是「测试通过但东西不工作」的形状。

修法是把语料改成与生产同分布（59 篇里保留 19 篇没摘要的），**不是去调阈值**。
改完之后：语义的最高负样本 0.629 → 0.660，最优错分 2 → 3。
**也就是说，第一版那个「语义比词面更好」的结论完全是语料偏差造出来的**——
如果当时没有 e2e 顶回来，这条 lane 会带着一个虚假的胜利结论合进去。

（这也是为什么第三节的表里没有 0.645：那个数是错语料标出来的，不该留在任何地方当参考。）

## 七、遗留问题（都没修，登记在此）

1. **词面阈值 `HIGH_AFFINITY = 0.75` 本身是可疑的**。同一份 30 条样本上，它自己的最优区间是
   [0.67, 0.71]，0.75 不在其中；在 0.75 上它有 1 条假阳性（h01 的邻近工作词面 0.857）。
   改它要重跑整条 P4 叙事（报告口径说明、e2e 期望、README），超出本 lane 所有权。
   **建议收口评审**：要么按新样本把它移到 0.70 附近，要么明确「保持 0.75，理由是……」。

2. **`local/bge-m3` 标定过但未登记**。要推翻「不换」的结论，需要：补样本（现在 n=47 太小，
   且全部由我一人撰写，有系统性偏好）、或换模型（多语言 + 对「同一件事 vs 同领域」更敏感）、
   或改判据（例如候选池内的相对显著性而非绝对余弦——但那会改变 R5 的语义，需要单独设计）。
   装置已经就位，重跑一次的成本是「录一次 fixture + 跑一个测试文件」。

3. **`openai` / `qwen` 两条 embedding 端点未实测**。本 lane 没有对应 key，baseUrl 按公开文档写，
   没录过 fixture，因此也不可能被登记阈值。有 key 的人跑一次录制即可核实。

4. **bge-m3 在长输入上不稳定**。试 `EMBED_ABSTRACT_CHARS = 2000` 时，e10 那篇的相似度从
   0.745 塌到 0.306，且 Ollama 侧偶发 runner 崩溃；1000 字符下三次独立测量逐位可复现。
   最终选 1000，但**没有查清 2000 那次塌陷的根因**，如实记录。

5. **`tests/fixtures/embeddings/local-bge-m3.json` 有 1.9 MB**（149 条 × 1024 维浮点）。
   这是真实录制的响应体，不做后处理（改了就不是「真实录制」，`bodySha256` 也对不上）。
   如果收口觉得仓库体积敏感，可选方案是改用更小维度的模型重录，而不是压缩既有 fixture。

6. **语义口径的约束分支目前只有测试在走**（生产表为空 ⇒ 恒走词面）。
   为此在 `NoveltyDeps` 上开了 `semanticThresholds` 注入位，让这条分支被完整测到，
   而不是变成「哪天真登记了阈值才第一次被执行」的死角。这是有意的取舍，登记在此。
