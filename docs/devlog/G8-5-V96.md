# G8-5 · V96 state.json 原子写

**日期** 2026-09-11 · **分支** `fix/G5-V96-state-atomic-write` · **闸门** G-5

## 问题
`ProjectManager.writeState` 是裸 `writeFileSync`（截断 + 写）。两步之间进程被 kill → `state.json` 是空文件或半个 JSON → `readState()` 的 catch 退回空状态：currentProject 与所有 session→项目绑定一次性丢失。

## 改动 `backend/src/project/manager.ts`
- `writeState`：同目录 `state.json.<pid>.<rand>.tmp` → `writeSync` → `fsyncSync` → `renameSync` 覆盖主文件；rename 失败清 tmp 后原错误冒泡。
- 与 C-1 锁同一临界区：`withStateLock` 维护 `stateLockDepth`，`writeState` 在锁外调用直接抛 `ProjectError`（四个调用点本来都在锁内，这是防回归的护栏）。

## 测试 `tests/unit/v96_state_atomic_write.test.ts` 3 条
1. 每次写 inode 变化（rename 的可观测特征）、目录无 `.tmp` 残留、锁已释放。
2. kill 模拟：目录里残留别进程写一半的 `.tmp`，主文件读取不受影响；下一次写仍是完整 JSON。
3. 连续 50 次 bindSession 每次读回都可解析。
- **阴性对照**：writeState 改回裸 writeFileSync → 第 1 条红（2 pass / 1 fail）；还原 3/3。
- unit+concurrency+timeout 2331/0；typecheck clean。

## 未做
- 残留 `.tmp` 的清扫（只有别进程 crash 才会留下，无害；readState 不会读它）。
- 项目 `meta.json` 的 `writeMeta` 仍是裸写——不在 V96 范围（V96 点名 state.json），登记到 β lane V85 项目锁一并看。
