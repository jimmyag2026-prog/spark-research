# G8-3 · V93 预算闸 TOCTOU：在飞预留 + 实时重读

**日期** 2026-09-11 · **分支** `fix/G3-V93-budget-inflight` · **闸门** G-3

## 问题（外部 review P1-2，代码级确认）
1. 闸检查与记账隔着整个 `await llm.call`：`Promise.all` 下 N 个在飞全先过闸后记账，$0.1 闸放行 10 个 $0.03。
2. 跨进程 `priorKnownCostUsd` 只在构造时读一次：两个进程并发跑 `lit read --all` 可双倍花钱。
3. 无发前预检：单次调用可花掉预算 158%（自家测试实锤）。

## 改动
- `backend/src/llm/budget.ts`
  - `BudgetLedger.tryReserve(estimateUsd) → BudgetReservation | null`：判 `known + inFlight + 估价 > maxCostUsd`，通过则同步记入 `inFlightUsd/inFlightCalls`；有父账本先向父预留（全局上限拦"每个子没超、加起来超"的在飞版）。`reserve()` 抛错版。
  - `BudgetReservation.settle(usage, opts)`：释放预留 → `record()`；`release()`：只释放（上游抛错/取消）。两者幂等。
  - `snapshot()` 新增 `inFlightUsd` `inFlightCalls`；`exceeded` 语义不变（只看已结算）。
  - `estimateCallCostUsd(messages, options, {provider, model})`：输入按 ≈3 字符/token 粗估、输出按 `maxTokens ?? 4096`，用 `priceFor` 上限价；查不到单价 **返回 null 不是 0**。
- `backend/src/usage/ledger.ts` `usageTrackingLlm.call`
  - 闸：`live = store.totals().knownCostUsd`（**每次实时重读**）+ `ledger.inFlightUsd` + 本次估价；`committed >= budget || committed + estimate > budget` → `kind:"budget"` 拒绝，消息里三项分列。
  - 过闸即 `tryReserve(estimate)`（同步段内，TOCTOU 封口）；上游 throw → `release()`；返回 → `settle()`（替代原 `record()`）。
  - 新增 `estimateUsd` 注入点（测试用）。未定价模型估价按 0 预留（拒绝未定价是 G-4 的事）。
- `backend/src/llm/router.ts`：`providerForModel` 导出（闸在发前需要知道 provider 查价）。
