### 实测中发现的新 bug（审查者独立发现）

**N1【P2】usage.jsonl 的 `model` 字段可被写成对象 → 面板渲染 `[object Object]`**
- 复现：全套件连跑 Playwright 时，e2e-lab 项目台账出现 4 条 `model` 为对象的记录，按模型表渲染成 `[object Object]`。
- 根因链：`tests/helpers/ideation_scenario.ts:72` 的 `ScriptedLlm.call(messages, model)` 不像真 `LLMRouter`（`router.ts:163-166` 会把 `CallOptions` 归一化成字符串）那样处理第二个参数 → 调用方传 `CallOptions` 时 `res.model` 即对象 → `usage/ledger.ts:187` 虽然类型标注 `model: string` 但**不做任何校验**直接落盘 → 前端聚合表出现 `[object Object]`。
- 修复：ledger 落盘前校验 `typeof model === "string"`（否则记 `"(unknown)"` 并计入 corrupt/告警）；ScriptedLlm 补一行与 Router 相同的归一化。

**N2【P2】E2E ⑱「用量面板」是顺序依赖测试，全套件连跑 3/3 必挂**
- `workbench.spec.ts:616-619` 的前提「fixture LLM 从不走 usageTrackingLlm、无 usage.jsonl」**不成立**：server context 的 `llmFor()` 会给 lit/ideation 路由包 usage 跟踪（`server/context.ts:124-147`），套件中先行的全流程测试已给 e2e-lab 写入 17 条记录 → 空态断言必失败。
- 同时 **CI 不跑 E2E**（`.github/workflows/ci.yml` 只有单测+冒烟），此失败永远不会挡发布。
- 修复：⑱ 前置清理该项目的 usage.jsonl（或改用独立新项目）；把 E2E 纳入 CI 或至少 nightly。

**N3【P3】缺 rdkit 时 chem 测试 10 个 fail 而非 skip**
- pydeseq2/scanpy 缺依赖时优雅 skip（探测+提示），rdkit 缺失时却硬 fail（`rdkit_unavailable` vs 期望 `invalid_smiles`）。新贡献者 clone 后跑 `bun test` 会先看到 10 个红。建议统一成探测→skip。

**N4【P3】版本号不一致**: `package.json` 0.6.0 vs `pyproject.toml` 0.2.0（Python 侧未随版本走）。

## 二、深度代码审查发现（按优先级）

### P0（发布前应修）

**P0-1｜`backend/src/project/manager.ts:174-279` 未传 `--project` 的会话受全局指针支配 + `state.json` 裸写无锁**
- `defaultProject()` 返回的是全局共享的 `currentProject` 指针，不是固定 slug：任何会话执行 `project new/open` 会改写指针，其他未传 flag 的会话**后续写操作立刻切到别的项目目录**。
- `readState→改→writeState`（:222-238）是裸 `writeFileSync` 的 read-modify-write：无锁、非原子、无跨进程互斥——四个并行会话高频 bindSession 时竞态窗口大，崩溃还可留下截断 JSON（静默状态清零）。
- 修复：① 无 flag 时走 `projectForSession(sessionId)`（代码里已有，CLI 收口未用）或 env + 固定 default 兜底；② state.json 改临时文件+rename 原子写，更新用 `O_CREAT|O_EXCL` lockfile 串行化；③ `create()` 的 exists→mkdir TOCTOU 用 `recursive:false` 抢占。

### P1

**P1-1｜`reviewer/rules.ts:96,296` 中文引用对两道核验门完全不可见——「0 伪造」保证在主推场景有洞**
- `CITATION_TOKEN` 字符集不含汉字（注释自述「key 允许字母数字与 -_:」），而 E-5 特意让 bibtex key 保留汉字（`literature/export.ts:38-48`）。后果双向坏：伪造 `[@李某2023神经解码]` → 不解析 → 核验与 LLM judge 全跳过（**绕过**）；草稿只引中文 key → `citedKeys()` 空 → 误判「没有任何引用」而生成失败（**误报**）。AMiner 中文检索正是本版主推场景。
- 修复：key 字符集加 `\p{Script=Han}`（连带 :296 强断言句检测），补「伪造中文 key → hard finding」对抗测试。

**P1-2｜`usage/ledger.ts:160-184` 预算闸非原子——在飞请求可集体越闸**
- 闸检查与记账隔整个 `await llm.call`，`Promise.all` 批量判定时 4 个在飞调用全先过闸后记账；跨进程则因 `priorKnownCostUsd` 只在构造时读一次而互不知情。教科书 TOCTOU。
- 修复：闸检查实时重读 `store.totals()`；进程内按预估价先冻结额度（mutex 下预留，回包后结算）；至少在文档写明并发越界上界。

**P1-3｜`llm/providers/registry.ts:50-167` 无价可查时预算闸完全失效且无警告**
- `priceFor` 返回 null → 调用全进 `unknownCostCalls` → `knownCostUsd` 恒 0 → **闸永不触发**（g3 测试甚至把这个行为钉成断言）。anthropic 一等 provider 单价表零条目；用户挂 `--budget-usd 5` 跑 claude 实际无保护、启动无警告。
- 修复：wrapper 构造时 `priceFor(默认模型)==null` 立刻 stderr 告警「预算闸对这些调用无效」；支持 `SPARK_LLM_PRICING_JSON` 用户供价（并拒绝负数单价）。

**P1-4｜`server/context.ts:124-169` + `agents/orchestrator.ts:294` agent 会话的 LLM 花费不入账**
- OrchestratorAgent 自持裸 Router，plan/explore/summarize 及子代理调用绕过 usage.jsonl → server 模式下 usage 面板**系统性少报**。context.ts:159 自己写着「所有带项目上下文的 LLM 消费一律经这里」——agent 路径是反例。
- 修复：给 OrchestratorAgent 注入 `usageTrackingLlm({command:"agent-session", project})` 包装。

**P1-5｜`server/routes/lab.ts:185-257` 审批门可经无鉴权本机 HTTP 旁路**
- approval gate 的设计目的（`approval/gate.ts:6-29` 自述）是「能跑 Bash 的 agent 不能自己批准湿实验」；CLI 要 TTY+yes。但 HTTP 面 `POST /api/lab/experiments/:id/approve` 只要求 `{"actor":"任何人名"}`（非空即可，自报无核验），随后 simulate 即执行编译出的 Python 协议。本地恶意进程 curl 即可走完 design→approve→execute，V19 门退化成注释；接真实 Opentrons 后即 P0（app.ts:87 自己承认）。
- 修复：把 approve/simulate 撤出 HTTP（照 compute dispatch 口径弹「去终端跑」），或要求 server 启动时生成的一次性确认 token。

## 三、做得好的点（保持）

1. **「未知≠0」三层口径统一**：types/账本/CLI/UI 四处一致，没有一处把未知折成 0（`usage/cli.ts:118`、前端 `unknown-cost-warning`）。
2. **安全设计上乘**：默认绑 127.0.0.1 无逃生门、写请求双闸（Content-Type+Origin）、argv-only 执行纪律全域一致、secrets 0600 + redactSecrets、compute 上传 deny-list fail-closed + 派发前逐文件重验。
3. **门禁即测试**：用测试扫描源码禁止 CLI 裸调 `defaultProject()`（r2_p0 门禁），把架构约束固化成可执行防线。
4. **乐观并发 CAS**：records 的 `expectedRev` 拒绝静默覆盖，且有机制级测试。
5. **引用核验多层体系**：白名单+回灌重试+独立 judge+hard/soft 分级+对抗测试套件——机制确实存在（只是在中文场景有 P1-1 的洞）。
6. **AMiner 拆词兜底克制且诚实**：上限 4 词、串行、失败进 note、5 条边界单测，机制与发布描述一致。
7. **BACKLOG 登记纪律**：已知限制全部如实登记有去向，发布声明无虚报（仅措辞需打限的两条见上）。

## 四、修改意见总排序（建议的修复顺序）

1. **P0-1** state.json 原子写+锁 + 无 flag 会话脱离全局指针 —— 直接支撑「并发零污染」声明
2. **P1-1** 引用 key 字符集加 Han + 对抗测试 —— 堵住主推场景的「0 伪造」洞
3. **P1-5** HTTP 审批旁路（撤出口或加一次性 token）—— 接真实设备前必须
4. **P1-2/P1-3** 预算闸原子化 + 无价模型告警 —— 花钱有闸的承诺收口
5. **P1-4** agent 会话入账 —— usage 面板数字可信
6. N1/N2（[object Object]、E2E ⑱ 顺序依赖）+ E2E 进 CI
7. 其余 P2 按表推进；P3 随迭代

**回归防线建议**：仓库内补一条真正的并发 e2e（4 子进程、各带/不带 --project、断言 records 互不串写），否则「四会话零污染」永远只是口头实测。
